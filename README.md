# Портфолио QA-инженера: Учебный проект «Яндекс.Самокат»

Привет! Меня зовут Алексей. Здесь собраны артефакты моего дипломного проекта в рамках курса «Инженер по тестированию» от Яндекс.Практикума. 

**Цель проекта:** Комплексное тестирование учебного приложения «Яндекс.Самокат» (веб, мобильное приложение, API, база данных).

## 🛠 Инструменты и технологии
*   **Веб-тестирование:** Google Таблицы, DevTools.
*   **Мобильное тестирование:** Android Studio (эмулятор).
*   **API-тестирование:** Postman.
*   **Работа с БД:** SQL (SELECT, FROM, WHERE, JOIN).
*   **Анализ трафика:** Charles.
*   **Тест-дизайн:** Классы эквивалентности, граничные значения, чек-листы, тест-кейсы, баг-репорты.

## 📂 Структура проекта
*   `01_Web_Testing` — чек-лист на экран «Статус заказа» (100 проверок), таблица валидации полей формы заказа (позитивные/негативные проверки, граничные значения), баг-репорты.
*   `02_Mobile_Testing` — тест-кейсы для мобильного приложения, проверка UI и функциональности в эмуляторе.
*   `03_API_Testing` — Postman-коллекция, чек-лист проверки эндпоинтов (коды ответов, структура JSON, негативные сценарии).
*   `04_Bug-Reports` — Баг репорты, заведенные во время работы.

## 🐞 Топ найденных багов (Выдержка из баг-трекера)

В ходе тестирования веб-приложения было найдено и оформлено **более 100 багов**. Вот небольшой список:

### 1. Некорректная валидация поля «Имя» (двойное имя с дефисом)
*   **ID:** YSBUG-24
*   **Шаги:** Открыть форму заказа → Ввести в поле «Имя» значение `Жан-Поль` → Оформить заказ.
*   **Ожидаемый результат:** Заказ успешно оформляется (дефис разрешен требованиями).
*   **Фактический результат:** Появляется ошибка валидации, заказ не создается.

### 2. Поле «Адрес» принимает только цифры
*   **ID:** YSBUG-27
*   **Шаги:** Открыть форму заказа → Ввести в поле «Адрес» значение `111222`.
*   **Ожидаемый результат:** Появляется сообщение об ошибке (адрес не может состоять только из цифр).
*   **Фактический результат:** Система пропускает значение, заказ оформляется.

### 3. Кнопка «Отменить заказ» остается активной, когда курьер уже в пути
*   **ID:** YSBUG-17
*   **Шаги:** Сделать заказ → Дождаться, пока курьер примет заказ → Перейти на экран «Статус заказа» → Нажать «Отменить заказ».
*   **Ожидаемый результат:** Кнопка недоступна (некликабельна), так как отмена невозможна.
*   **Фактический результат:** Заказ отменяется, что ломает логику работы курьера.

### 4. Окно отмены заказа не закрывается кликом по свободной области
*   **ID:** YSBUG-94
*   **Шаги:** Перейти на экран «Статус заказа» → Нажать «Отменить заказ» → Кликнуть в любую точку экрана вне всплывающего окна.
*   **Ожидаемый результат:** Всплывающее окно закрывается, пользователь возвращается к экрану статуса заказа.
*   **Фактический результат:** Окно остается открытым, закрыть его можно только через кнопку «Назад» или Escape (что тоже сломано, баг YSBUG-95).

### 5. UI: Текст не переносится на новую строку
*   **ID:** YSBUG-5, YSBUG-6, YSBUG-7, YSBUG-8 и др.
*   **Описание:** Если Имя, Фамилия, Адрес или Станция метро не умещаются в одну строку, они не переносятся, а наезжают на соседние элементы интерфейса (проверялось по макетам в Figma).
